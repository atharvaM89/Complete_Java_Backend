## 1️⃣ Introduction to Servlets

---

### 🔹 What is a Servlet?

A **Servlet** is a **Java-based server-side component** that:

- Runs inside a **Servlet Container**
- Handles **HTTP requests**
- Generates **dynamic responses** (HTML, JSON, text, etc.)

👉 In simple words:

> Servlet = Java class that handles web requests and responses
> 

---

### 🔹 Why Do We Need Servlets?

Before servlets, web applications were **static**:

- HTML pages showed fixed content
- No database interaction
- No user-specific behavior

But real-world applications need:

- Login systems
- Personalized dashboards
- Data processing
- Database access

👉 **Servlets enable dynamic web applications**

---

### 🔹 Real-World Example

| Scenario | Without Servlet | With Servlet |
| --- | --- | --- |
| Login System | Static HTML only | Validates user, creates session |
| E-commerce | Fixed pages | Dynamic products, cart, orders |
| Banking | Not possible | Secure transactions |

---

## 2️⃣ Problems with CGI & How Servlets Solve Them

---

### 🔹 What is CGI (Common Gateway Interface)?

CGI was an early way to create dynamic web content.

**How CGI Works:**

1. Browser sends request
2. Server starts a **new OS process**
3. Program executes
4. Process ends

---

### ❌ Problems with CGI

| Problem | Explanation |
| --- | --- |
| Performance | New process for every request |
| Memory Waste | High memory usage |
| Slow Response | Process creation overhead |
| Scalability | Cannot handle many users |

---

### ✅ How Servlets Solve CGI Problems

| CGI | Servlet |
| --- | --- |
| New process per request | Single servlet instance |
| OS-level overhead | Lightweight Java threads |
| Poor performance | High performance |
| Not scalable | Highly scalable |

👉 **Servlets are multithreaded and reusable**

---

### 🔹 Key Improvement

> Servlet = One class → Multiple requests → Multiple threads
> 

---

## 6️⃣ Servlet Container (VERY IMPORTANT)

---

### 🔹 What is a Servlet Container?

A **Servlet Container** is a runtime environment that:

- Loads servlet classes
- Manages servlet lifecycle
- Handles multithreading
- Provides APIs (request, response, session)

👉 **Servlets NEVER run standalone**

---

### 🔹 Common Servlet Container

- **Apache Tomcat** (most popular)

---

### 🔹 Responsibilities of Servlet Container

### 1️⃣ Servlet Loading

- Loads servlet class at startup or first request

### 2️⃣ Lifecycle Management

- Calls:
    - `init()`
    - `service()`
    - `destroy()`

### 3️⃣ Multithreading

- Creates a new thread for each request
- Uses **same servlet instance**

### 4️⃣ Security

- URL protection
- Authentication support

### 5️⃣ Communication

- Creates `HttpServletRequest`
- Creates `HttpServletResponse`

---

Without container:

- No lifecycle

## 4️⃣ Servlet API Overview

---

### 🔹 What is Servlet API?

The **Servlet API** is a **set of Java interfaces and classes** provided by Java EE / Jakarta EE that allows:

- Communication between **Servlet Container** and **Servlet**
- Access to **request, response, session, config, context**, etc.

👉 Without Servlet API:

- Servlet cannot read request
- Servlet cannot send response
- Servlet cannot manage session

---

### 🔹 Packages in Servlet API (Used in Real Projects)

| Package | Purpose |
| --- | --- |
| `javax.servlet` | Generic (protocol-independent) servlet features |
| `javax.servlet.http` | HTTP-specific features (MOST USED) |

> ⚠️ Note:
> 
> 
> In modern projects, package name may be `jakarta.servlet`, but **concepts remain 100% same**.
> 

---

## 🔹 Important Interfaces & Classes (Workflow Order)

---

### 1️⃣ Servlet Interface (Root Interface)

```java
publicinterfaceServlet {
voidinit(ServletConfig config);
voidservice(ServletRequest req, ServletResponse res);
voiddestroy();
}

```

### Why it exists:

- Defines **contract** between servlet and container

### Why we don’t use it directly:

- Too low-level
- Protocol-independent
- No HTTP methods

---

### 2️⃣ GenericServlet (Abstract Class)

```java
publicabstractclassGenericServletimplementsServlet

```

### Features:

- Implements `Servlet` interface
- Provides default implementations
- Protocol-independent

### Why still not used much:

- No HTTP support (GET, POST, etc.)

---

### 3️⃣ HttpServlet (MOST IMPORTANT)

```java
publicabstractclassHttpServletextendsGenericServlet

```

### Why HttpServlet is used in real projects:

- Supports HTTP methods
- Clean separation of logic
- Industry standard

---

### 🔹 HttpServlet Methods

| Method | Used For |
| --- | --- |
| `doGet()` | Read-only requests |
| `doPost()` | Form submission |
| `doPut()` | Update |
| `doDelete()` | Delete |

> 👉 90% real-world apps use doGet() and doPost()
>

## 5️⃣ Servlet Life Cycle (🔥 VERY IMPORTANT – INTERVIEW FAVORITE)

---

### 🔹 What is Servlet Life Cycle?

The **Servlet Life Cycle** defines:

- **How servlet is created**
- **How it handles requests**
- **How it is destroyed**

> 💡 Controlled completely by Servlet Container
> 

---

## 🔹 Life Cycle Stages

![https://media.geeksforgeeks.org/wp-content/uploads/20250205142106489023/State-of-sevlet-life-cycle.webp](https://media.geeksforgeeks.org/wp-content/uploads/20250205142106489023/State-of-sevlet-life-cycle.webp)

![https://www.tutorialspoint.com/servlets/images/servlet-lifecycle.jpg](https://www.tutorialspoint.com/servlets/images/servlet-lifecycle.jpg)

---

### 🔹 1️⃣ Loading & Instantiation

- Servlet container:
    - Loads servlet class
    - Creates **only ONE object**

```java
MyServletservlet=newMyServlet();

```

📌 Happens:

- At server startup (if `load-on-startup`)
- OR first request

---

### 🔹 2️⃣ `init()` Method

```java
publicvoidinit()throws ServletException {
// executed only once
}

```

### When is `init()` called?

- Immediately after servlet object creation
- Only **ONCE** in servlet lifetime

### Why `init()` is needed:

- Resource initialization
- Database connection
- Reading config parameters

---

### 🔹 Real-World Use of `init()`

```java
publicvoidinit() {
    System.out.println("DB Connection created");
}

```

> ❌ Never put request-specific logic in init()
> 

---

### 🔹 3️⃣ `service()` Method

```java
publicvoidservice(ServletRequest req, ServletResponse res)

```

### What `service()` does:

- Called for **EVERY request**
- Decides which method to call:
    - `doGet()`
    - `doPost()`

---

### 🔹 Internal Working of HttpServlet

```java
protectedvoidservice(HttpServletRequest req, HttpServletResponse res) {
if (method == GET) doGet();
elseif (method == POST) doPost();
}

```

👉 **Developers usually override `doGet()` / `doPost()` instead of `service()`**

---

### 🔹 4️⃣ `doGet()` Method

```java
protectedvoiddoGet(HttpServletRequest req,
                     HttpServletResponse res)

```

Used when:

- URL hit directly
- Data is read-only
- Idempotent operations

---

### 🔹 5️⃣ `doPost()` Method

```java
protectedvoiddoPost(HttpServletRequest req,
                      HttpServletResponse res)

```

Used when:

- Form submission
- Sensitive data
- Data modification

---

### 🔹 6️⃣ `destroy()` Method

```java
publicvoiddestroy() {
// cleanup
}

```

### When is `destroy()` called?

- Server shutdown
- Application redeploy

### Why it is needed:

- Close DB connections
- Release resources

---

```
ClassLoaded
↓
ServletObjectCreated
↓
init()→ once
↓
service()
↓
doGet()/ doPost()→ multiple times
↓
destroy()→ once

```

## 6️⃣ Creating a Servlet (REAL-WORLD WAY)

---

### 🔹 How a Servlet Is Created in Practice

In real applications:

- We **never implement `Servlet` directly**
- We **extend `HttpServlet`**
- We **override `doGet()` / `doPost()`**

👉 This aligns with **HTTP request–response workflow**

---

## 🔹 Basic Steps to Create a Servlet

1. Create a Java class
2. Extend `HttpServlet`
3. Override `doGet()` or `doPost()`
4. Map servlet to a URL
5. Deploy on server

---

## 🔹 Minimal Servlet Structure

```java
import javax.servlet.http.*;
import javax.servlet.*;
import java.io.*;

publicclassFirstServletextendsHttpServlet {

protectedvoiddoGet(HttpServletRequest request,
                         HttpServletResponse response)
throws IOException {

        response.setContentType("text/html");
PrintWriterout= response.getWriter();
        out.println("<h1>Hello Servlet</h1>");
    }
}

```

---

## 🔹 Why We Extend `HttpServlet`

| Reason | Explanation |
| --- | --- |
| HTTP support | GET, POST, PUT, DELETE |
| Cleaner design | Separate methods |
| Industry standard | Used everywhere |

## 7️⃣ doGet() vs doPost() (VERY IMPORTANT)

---

### 🔹 doGet()

Used when:

- Data is **not sensitive**
- Request is **read-only**
- Bookmarking is allowed

Example:

```
/search?keyword=java

```

---

### 🔹 doPost()

Used when:

- Data is **sensitive**
- Data is **large**
- Data modifies server state

Example:

```
Loginform
Registration
Payment

```

---

### 🔹 Comparison Table

| Feature | doGet() | doPost() |
| --- | --- | --- |
| Data visibility | URL | Request body |
| Security | Less | More |
| Data size | Limited | Large |
| Use case | Search | Login |

📌 **Interview Rule**

> GET → Fetch data
> 
> 
> POST → Submit data
>

## 9️⃣ Servlet Configuration Methods

There are **TWO** ways to configure a servlet:

1. **web.xml** (old but important)
2. **@WebServlet annotation** (modern & preferred)

---

## 🔹 Method 1: web.xml Configuration

### 📄 web.xml

```xml
<web-app>

<servlet>
<servlet-name>first</servlet-name>
<servlet-class>FirstServlet</servlet-class>
</servlet>

<servlet-mapping>
<servlet-name>first</servlet-name>
<url-pattern>/hello</url-pattern>
</servlet-mapping>

</web-app>

```

---

### 🔹 How This Works

| URL | Servlet |
| --- | --- |
| `/hello` | `FirstServlet` |

Browser hits:

```
http://localhost:8080/app/hello

```

---

### 🔹 When web.xml Is Used Today

- Legacy applications
- Centralized configuration
- Interview questions

---

## 🔹 Method 2: @WebServlet Annotation (REAL PROJECTS)

```java
@WebServlet("/hello")
publicclassFirstServletextendsHttpServlet {
protectedvoiddoGet(HttpServletRequest req,
                         HttpServletResponse res)
throws IOException {
        res.getWriter().println("Hello");
    }
}

```

✔ No XML

✔ Clean code

✔ Industry standard

---

### 🔹 Multiple URL Patterns

```java
@WebServlet({"/hello", "/welcome"})

```

---

## 🔹 Which Is Better?

| Criteria | web.xml | Annotation |
| --- | --- | --- |
| Readability | Low | High |
| Modern apps | ❌ | ✅ |
| Interview | ✅ | ✅ |

📌 **Answer in interview:**

> “Annotations are preferred, but web.xml is still supported.”
>

## 15️⃣ How Servlet Multithreading Works Internally

---

### 🔹 Step-by-Step Execution

1. Client sends request
2. Servlet Container receives request
3. Container **creates a new thread**
4. Thread calls `service()` → `doGet()` / `doPost()`
5. Same servlet instance is used
6. Thread ends after response

---

### 🔹 Key Rule (INTERVIEW GOLD)

✔ **Servlet object is created only once**

✔ **Thread is created per request**

---

## 16️⃣ Why This Is Dangerous (Thread Safety Problem)

---

### 🔹 The Core Issue

Because:

- Multiple threads access **same servlet object**
- Shared data can be corrupted

👉 This leads to **race conditions**

---

### 🔹 Example of Problematic Code 🚫

```java
@WebServlet("/count")
publicclassCounterServletextendsHttpServlet {

intcount=0;// INSTANCE VARIABLE ❌

protectedvoiddoGet(HttpServletRequest req,
                         HttpServletResponse res)
throws IOException {

        count++;
        res.getWriter().println("Count: " + count);
    }
}

```

---

### 🔹 What Can Go Wrong?

- Thread A reads `count = 5`
- Thread B reads `count = 5`
- Both increment → result = 6 (WRONG)

---

## 17️⃣ Thread-Safe vs Non-Thread-Safe Data

---

### 🔹 SAFE (Always Thread-Safe)

✔ Local variables

✔ Method parameters

✔ Request object

✔ Response object

✔ Session object (per user)

---

### 🔹 UNSAFE (Needs Care)

❌ Instance variables

❌ Static variables

❌ ServletContext attributes

---

## 18️⃣ Why Request & Session Are Safe

---

### 🔹 HttpServletRequest

- Created **per request**
- Used by **one thread only**

---

### 🔹 HttpSession

- One session per user
- Usually accessed by **one thread at a time**

(But still not fully thread-safe if multiple tabs)

---

## 19️⃣ How to Write Thread-Safe Servlets (BEST PRACTICES)

---

## ✅ Rule 1: Never Use Instance Variables for Request Data

❌ Wrong

```java
String username;// instance variable

```

✔ Correct

```java
Stringusername= req.getParameter("user");

```

---

## ✅ Rule 2: Use Local Variables Only

Local variables live on **thread stack**

✔ Safe

✔ Recommended

---

## ✅ Rule 3: Synchronization (Use Carefully)

---

### 🔹 Using synchronized block

```java
synchronized(this) {
    count++;
}

```

⚠️ Drawback:

- Reduces performance
- Blocks other users

👉 Use **only when unavoidable**

---

## ✅ Rule 4: Use Thread-Safe Objects

Examples:

- `AtomicInteger`
- Concurrent collections

```java
AtomicIntegercount=newAtomicInteger();

count.incrementAndGet();

```

## 16️⃣ Servlet Design Best Practices (MUST FOLLOW)

---

## ✅ 1. Keep Servlets as Controllers Only

Servlets should:

- Read request
- Call business logic
- Forward response

❌ Don’t put heavy logic inside servlet

✔ Follow MVC pattern:

```
Servlet (Controller)
   ↓
Service/ DAO (Logic)
   ↓
JSP (View)

```

---

## ✅ 2. Use doGet() and doPost() Properly

| Action | Method |
| --- | --- |
| Fetch data | GET |
| Submit data | POST |
| Login | POST |
| Logout | GET |

📌 Interview line:

> “GET is idempotent, POST modifies state”
> 

---

## ✅ 3. Always Validate User Input

Never trust client input.

---

### 🔹 Example: Input Validation

```java
StringageStr= req.getParameter("age");

if(ageStr ==null || !ageStr.matches("\\d+")) {
    res.getWriter().println("Invalid Age");
return;
}

```

✔ Prevents runtime exceptions

✔ Improves security

---

## ✅ 4. Proper Resource Management

---

### 🔹 Wrong ❌

```java
Connectioncon= DriverManager.getConnection();
// not closed

```

---

### 🔹 Correct ✔

```java
try {
// DB logic
}finally {
    con.close();
}

```

✔ Prevents memory leaks

---

### 🔹 Step-by-Step Execution Flow


## 17️⃣ MOST ASKED SERVLET INTERVIEW QUESTIONS (WITH ANSWERS)

---

## 🔥 Core Fundamentals

### ❓ What is a Servlet?

**Answer:**

A servlet is a **server-side Java component** that handles HTTP requests and generates dynamic responses.

---

### ❓ Why are Servlets faster than CGI?

**Answer:**

Servlets use **multithreading** instead of creating a new process for every request.

---

### ❓ Who manages the servlet lifecycle?

**Answer:**

The **Servlet Container** manages the lifecycle.

---

## 🔥 Lifecycle & API

### ❓ How many servlet objects are created?

✔ **Only one object per servlet**

---

### ❓ How many threads are created?

✔ **One thread per request**

---

### ❓ Difference between service() and doGet()?

| service() | doGet() |
| --- | --- |
| Called by container | Called by service() |
| Generic | HTTP specific |

---

### ❓ Can we override service()?

✔ Yes, but **not recommended**

---

## 🔥 Request & Response

### ❓ How does servlet read form data?

✔ `request.getParameter()`

---

### ❓ Where is request data stored?

✔ Inside `HttpServletRequest`

---

### ❓ Is HttpServletRequest thread-safe?

✔ Yes (one per request)

---

## 🔥 forward vs redirect

### ❓ Difference between forward() and sendRedirect()?

| forward | redirect |
| --- | --- |
| Server-side | Client-side |
| Same request | New request |
| URL unchanged | URL changed |
| Faster | Slower |

---

### ❓ When to use redirect?

✔ After login / logout

✔ When creating new request

---

## 🔥 ServletConfig vs ServletContext

### ❓ Difference?

| ServletConfig | ServletContext |
| --- | --- |
| One per servlet | One per app |
| Local config | Global config |
| Not shared | Shared |

---

### ❓ Where to store DB connection?

✔ ServletContext

---

## 🔥 Session Management

### ❓ Why is session needed?

✔ HTTP is stateless

---

### ❓ Where is session stored?

✔ On server

---

### ❓ How is session tracked?

✔ Cookie (`JSESSIONID`)

---

### ❓ Difference between Cookie & Session?

| Cookie | Session |
| --- | --- |
| Client-side | Server-side |
| Less secure | More secure |

---

### ❓ How to logout user?

✔ `session.invalidate()`

---

## 🔥 Multithreading

### ❓ Are servlets multithreaded?

✔ Yes

---

### ❓ Why instance variables are dangerous?

✔ Shared among threads → race conditions

---

### ❓ How to make servlet thread-safe?

✔ Use local variables

✔ Avoid shared mutable state

---

## 🔥 Exception Handling

### ❓ Best way to handle exceptions in servlets?

✔ Centralized error handling using `web.xml`

---

### ❓ Should we show stack trace to user?

❌ Never

---

## 🔥 Security & Best Practices

### ❓ Why POST is preferred for login?

✔ Data not visible in URL

---

### ❓ How to prevent session hijacking?

✔ HTTPS + invalidate session
