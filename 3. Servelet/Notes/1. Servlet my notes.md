# A. How a Website Works (End-to-End Flow)

### 1 . Client–Server Interaction

When we open any website in a browser (for example: `https://example.com`), the browser acts as a **client** and requests data from a **server**.

- The **client sends a request**
- The **server processes the request**
- The **server sends a response back**

This request–response cycle is the foundation of web applications.

---

### 2 . IP Address

- Every device connected to the internet has a **unique IP address**
- Servers are also identified using IP addresses
- Example:

  ```
  142.250.182.14

  ```

But remembering IP addresses is difficult, so we use **domain names**.

What DNS Does?

DNS converts **human-readable domain names** into **IP addresses**.

Example:

```
google.com  →  142.250.182.14

```

DNS Mapping

- Website owners register their domain name (e.g., on GoDaddy)
- Domain name is mapped to a server’s IP address
- When a user searches the domain name:
  - Browser contacts DNS server
  - DNS server returns the corresponding IP address
  - Browser connects to that IP

📌 **This process is called DNS Mapping**

---

- A single server (same IP) can host **multiple applications**
- Port numbers identify **which application/service** to connect to

| HTTPS   | 443  |
| Tomcat  | 8080 |

### TCP / IP Explained

TCP (Transmission Control Protocol)

- Ensures **reliable data delivery**
- Uses sequence numbers
- Handles retransmission if data is lost

IP (Internet Protocol)

- Responsible for **routing packets**
- Sends packets to correct destination IP

📌 TCP + IP work together to deliver HTTP data reliably.

## Complete Request–Response Flow

1. User enters `https://example.com`
2. DNS lookup returns IP address
3. TCP connection established (3-way handshake)
4. HTTP request sent
5. TCP breaks data into packets
6. IP routes packets to server
7. Server processes request
8. HTTP response sent back
9. TCP closes connection

# Servlet Technology

### What is a Servlet?

A **Servlet** is a Java technology used to create **dynamic web applications**.

- Runs on the **server side**
- Handles HTTP requests
- Generates HTTP responses
- Acts as a **middle layer** between client and business logic

---

### What is a Web Application?

A **web application**:

- Runs on a server
- Accessed using a browser
- Used by multiple users simultaneously

📌 Without a server, a web application **cannot function**.

---

### What is a Server?

A **server** is a program that:

- Listens for client requests
- Processes requests
- Sends responses back

### Servlet Config & Servlet Context

### 🔹 ServletConfig

What is ServletConfig?

`ServletConfig` is an **object created by the servlet container (Tomcat)** to provide **configuration information to a specific servlet**.

👉 **One Servlet = One ServletConfig object**

It is mainly used to:

- Pass **initialization parameters** to a servlet
- Get servlet-specific configuration
- Access the `ServletContext` object

---

ServletConfig Lifecycle

1. Servlet container loads the servlet
2. Creates **ServletConfig object**
3. Calls `init(ServletConfig config)`
4. Passes `ServletConfig` to the servlet

📌 `ServletConfig` exists **as long as that servlet exists**

---

Where is ServletConfig Defined?

- Defined inside `web.xml`
- OR using annotations

web.xml Example

```xml
<servlet>
<servlet-name>MyServlet</servlet-name>
<servlet-class>com.app.MyServlet</servlet-class>

<init-param>
<param-name>username</param-name>
<param-value>admin</param-value>
</init-param>
</servlet>

```

---

Accessing ServletConfig in Servlet

```java
publicclassMyServletextendsGenericServlet {

publicvoidservice(ServletRequest req, ServletResponse res) {
ServletConfigconfig= getServletConfig();
Stringuser= config.getInitParameter("username");
    }
}

```

---

Important Methods of ServletConfig

| Method                          | Description                   |
| ------------------------------- | ----------------------------- |
| `getInitParameter(String name)` | Returns init parameter value  |
| `getInitParameterNames()`       | Returns all param names       |
| `getServletName()`              | Returns servlet name          |
| `getServletContext()`           | Returns ServletContext object |

---

Use Cases of ServletConfig

- Database credentials per servlet
- Page-specific configurations
- API keys used by one servlet only

### 🔹 ServletContext

What is ServletContext?

`ServletContext` is an **application-wide object** shared by **all servlets** in a web application.

👉 **One Web Application = One ServletContext**

---

ServletContext Lifecycle

- Created when **web application starts**
- Destroyed when **application stops**
- Shared among:
  - Servlets
  - JSP
  - Filters
  - Listeners

📌 It lives **longer than any servlet**

---
